# 翻译工艺规则

> 价值基准（每次翻译必须生效）：AGENTS.md §1.1——**保真优先于顺口**。社区通行叫法常比官方形顺口，但以消灭/变形 lore 为代价；官方名词是默认选择，模型生成的社区先验必须主动对抗。本条是所有工艺规则的判断支点，细则如下。

## 1. 翻译时优先利用上下文

翻译的核心工作是先通读原文、形成语义理解，再据此做术语判断与具体翻译。工程动作不能代替这一过程。逐条孤立翻译不是默认最佳方案。

处理一批实际文本时，先恢复并阅读足够大的连续语义单元：完整任务、完整对话分支、同一角色的相关台词、整本书信，或能说明剧情前后关系的文本集合。完成 XML 提取、结构化、索引、词典查询、哈希校验、批次切分或脚本处理，不等于获得了足够的翻译上下文。

脚本与程序负责提取、定位、排序、关联、词典检索、格式保护、写回和验证，让 Agent 更可靠地阅读、理解和交付文本；不要让工程流程取代阅读本身。当"继续写脚本 / 处理哈希 / 重建中间产物"与"继续通读原文 / 理清角色与称谓关系"竞争，且前者不是解决当前具体阻塞所必需时，优先后者。

对以下内容优先寻找上下文再翻译：`INFO`（NPC 台词）、`DIAL`（对话主题 / 玩家选项 / Topic）、`QUST`（任务名 / 目标 / 日志 / 阶段）、`BOOK`（书籍 / 信件 / 笔记）、角色 / 地点 / 派系 / 法术 / 装备 / 剧情专名。对话类文本尽可能结合所属任务、Topic / 分支、前后相邻台词、说话者身份、玩家选项与 NPC 回答的关系、当前剧情阶段。XML 无法提供足够上下文时，明确这是上下文缺失，不凭空补剧情。

## 2. 信息揭示顺序、角色知识边界与禁止剧透

保留原文的信息揭示顺序。因翻译提前暴露身份、真相、阵营关系、种族关系、人物关系、地点性质或其他剧情信息，是严重翻译事故。Agent 只能翻译"原文在当前文本位置允许玩家知道的信息"，不能把通读全文、世界观资料或后续剧情得来的真相提前写进译文。

警惕：专名与描述性通称；真名、化名、别名、绰号与伪装身份；古称、现代称呼与后世称呼；未知种族 / 势力与其后被揭示的真实身份；同一实体在不同角色、文化、时代或知识层级下的不同称谓；后续剧情才确认的亲缘、阵营、背叛、变身、来源或真实用途。

两个英文词即使在世界观层面最终指向同一实体，也不因此自动合并译名。原文选择了不同词形、称谓或描述时，默认差异可能具有叙事意义，确认无害前保留差异。例如：即使知道 `Falmer` 与 `Snow Elf` 存在身份关系，也不能在原文使用 `Falmer` 的位置提前译成"雪精灵"——这会破坏《黎明守卫》的身份揭示；`Maormer` / `Sea Elf` 同理。

完整通读带来的世界观真相用于避免误译、理解伏笔、保持前后一致，不用于把后见之明反向注入早期译文。

## 3. 原版词典的使用规则

`dictionary/` 下的官方英中 XML 是高优先级参考语料。目录采用目录语义：树下所有 XML 都是官方来源，不假设固定文件名、数量、子目录或 DLC 白名单，不基于已知文件名设优先级；新增 XML 自动参与查询。

优先用于：官方角色名、地名、派系名、法术 / 魔法效果 / 技能 / 装备术语、常见 UI 与交互文本、TES 世界观固定译法。

词典提供的是译名与用法证据，不是无条件语义替换表。命中只说明某译法在某些官方文本中成立，不自动证明两个不同英文术语在当前剧情中可以合并。专名、通称、别称、古称或描述性名称在原文中被明确区分时，即使词典表明它们最终指向同一对象，也先保留词汇层级差异，检查是否涉及剧情揭示、角色知识边界或文化视角。MOD 自创术语与原版术语冲突时，区分"原版固定译名"与"MOD 自创概念"。

**源文缺陷与 EDID 冲突时以源文字面为准**：同一字符串的 `Source` 与 `EDID` 语义不一致时（作者复制残留、字段未更新等），Dest 跟 `Source`，EDID 仅作参考与备注。依据：`Source` 是游戏实际展示的文本，Dest 不得凭空增补 EDID 语义；且源文是**另一个有效词**而非拼写错误时，意图无法从文本本身唯一确定。反例对照：2945 源文与 `AuridonHouseApartments` 不符，维持源文字面；435/436 `RACE:FULL` 源文均为 `Fire Demon`（EDID 实为 AncientGiant / FrostDemon）→ 均译「火魔」。

与**笔误类**分开：源文是同一名称的拼写错误、意图无歧义时，按预期形译（Annha 的源文变体 Anna、Synod Suppleant 的 Source 拼写 Supplant 均同译）。判据是“意图能否从文本本身唯一确定”，不是“EDID 说了什么”。

**名层与散文层分开**：同源词在专名层（`*:FULL` 物体/法术/地点名）必须统一；在同一描述句里作普通名词使用时可按中文习惯用另一词形。依据：前者的分裂是术语漂移（`Enochian Circle` 名层必统一），后者受句法约束（「打开一条逃生**通道**」通，「打开一条逃生**路线**」拗口）。判定时先问该处是“命名”还是“行文”。

## 4. 翻译风格

目标：像《天际》现有中文本地化的一部分，而非现代网络文本或机器直译。

默认要求：准确优先于华丽；中文自然，不保留无意义英文语序；人物口吻与身份和场景匹配；古朴感适度，不滥用文言；UI、任务目标与交互提示简洁；书籍、信件与剧情文本可适当提高文学性；同一角色、地点、派系、物品、概念的译名保持一致。不为了"像奇幻作品"添加原文不存在的信息、语气或修辞。

标点与字符：**中文引号一律用弯引号“”，不用日式「」**（gate CHAR001 机械拦截）；任务目标句（QUST:NNAM）句末标点随源文；分隔符按源文形态（` - ` 保留分隔，不替换为破折号）。

## 5. 按记录类型处理

不同 `REC` 类型共用一套机械策略。初步原则：

- `INFO:*`：优先保证人物口吻、上下文与指代正确。
- `DIAL:*`：简洁，注意它可能是玩家选项、Topic 名或对话标签。
- `QUST:*`：任务名可有风格；目标与日志优先清楚、自然、符合游戏 UI。**任务目标句（NNAM）的句末标点随源文**：源文带句末标点（句号/叹号/问号）时译文必须保留，由 `translation-fidelity-scan` 对 `QUST:NNAM` 的 `lost` 做机械校验（缺则 FAIL）；句末带「（可选）」类标记时标点置于标记之前（如「取得钥匙。（可选）」）。
- `BOOK:*`：结合全文上下文翻译，不逐句割裂。
- `MESG:*`：按实际用途区分标题、正文、按钮与系统提示。
- `MGEF:*` / `SPEL:*`：优先复用原版魔法术语与描述习惯。
- `WEAP:*` / `ARMO:*` / `MISC:*`：优先保证名称风格与术语一致性。
- `ACTI:*` / `FURN:*`：交互文本通常短而明确。
- `NPC_:*` / `CELL:*` / `WRLD:*`：名称必须检查是否已有官方或既定译法。

## 6. 长文本的忠实度要求（无条件规则）

长段落叙事（BOOK:DESC 书页、QUST:CNAM 长日志）是幻觉性偏差的高发区：句子读得通、字数也对，但事实被改了。以下五条从 Artaeum 长文本审查的实际缺陷归纳（每类均有 2 处以上实例），它们不是风格偏好，是**事实保真**：

- **连接词的逻辑关系必须保持**。`though/although`（让步）不得译成因果（「鉴于」），`since/because`（原因）不得译成让步（「虽然…但…」）。关系一换，论证方向就反了。
- **可能性程度不得升格**。`might/may/could/should` 与 `does not`（确定否定）各自保持原强度：「可能」不得译作「肯定」，「不会」不得译作「不一定」。
- **代词指代必须回到源文的先行词**。中文省略主语时容易丢线索：`they` 指前半句的迪德拉就不能译成「其他女巫」；`their horse` 的主语是马就不能换成「他们」。拿不准时写出先行词所指的名词。
- **不得自行推算源文未给出的数字**。源文列「五年前，再往前三年」就是两个间隔，不能心算成「八年前」；「千个附庸王国」是具体数，不能模糊成「众多」。
- **不得用背景知识修改源文描述**。译者知道阿尔贡是爬行类，也不得把源文的 `smooth, wet skin`（湿润）改成「干燥」；源文没写性别就不加「她/他」，没写数量就不补数词。

与本节的关系：§5「按记录类型处理」管体裁与用途，本节管长文本的语义忠实；两者同时适用。

## 7. 翻译与 KEEP：不对称原则（不做个案权衡）

**决策原则（成本不对称）**：漏译是事故——玩家一旦看见就是缺陷；多译即使不可见也无害。因此**默认翻译**，「保留原文」的举证责任永远在保留侧，且只接受「源文没有可译语言内容」这一类客观证据。不得以「玩家不可见」「开发残留」「测试用语」「与既有 KEEP 口径一致」为由保留原文——这些是**无法验证的猜测**，不是证据。

**唯一例外：源文不含可译语言内容**（以下三类之外一律翻译）：

1. **纯数字 / 纯符号**（如 `1`、`2`）—— 数字形态跨语言，不存在英译中。
2. **无序字符串**（密码、坐标、哈希等）—— 不是语言，翻译会改变其信息内容。
3. **整串构成单个格式 token**（如 `<Cool graphic>`）—— 翻译会产生不同 token，写回工具机械拒绝。

其余全部在翻译范围内：测试、调试、开发、废弃文本，**编辑器 ID 形态的显示名**（如 `SummersetWolfQ04MiscVampireWarnTopic`），玩家不可见的字符串，均照常翻译；译不出语义的按字面直译或音译（拟声串音译）。

**执行纪律（硬规则）**：出现「要不要译」的犹豫即为错误信号，按默认翻译执行并继续；不得为单条串展开利弊分析，也不得把此类取舍上交裁决。

**反例对照**：以上任一例外之外的 KEEP 均为错误处置，典型错例包括 `NEMO` / `Camera` / `Template`（已翻，参 gen155）、`OBSOLETE STAGE` / `TestQuest`（已翻）、`*Topic` 形态编辑器 ID（已翻，参 gen157）；以「玩家不可见」辩护这些 KEEP 不成立。

## 8. 按记录类型处理细化方向

这些规则随实际 MOD 样本细化；细化结果更新本 skill 或项目级 `GLOBAL.md`。
