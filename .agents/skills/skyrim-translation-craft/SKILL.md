# 翻译工艺规则

> 价值基准（每次翻译必须生效）：AGENTS.md §1.1——**保真优先于顺口**。社区通行叫法常比官方形顺口，但以消灭/变形 lore 为代价；官方名词是默认选择，模型生成的社区先验必须主动对抗。本条是所有工艺规则的判断支点，细则如下。

## 1. 翻译时优先利用上下文

翻译的核心工作是先通读原文、形成语义理解，再据此做术语判断与具体翻译。工程动作不能代替这一过程。逐条孤立翻译不是默认最佳方案。

处理一批实际文本时，先恢复并阅读足够大的连续语义单元：完整任务、完整对话分支、同一角色的相关台词、整本书信，或能说明剧情前后关系的文本集合。完成 XML 提取、结构化、索引、词典查询、哈希校验、批次切分或脚本处理，不等于获得了足够的翻译上下文。

脚本与程序负责提取、定位、排序、关联、词典检索、格式保护、写回和验证，让 Agent 更可靠地阅读、理解和交付文本；不要让工程流程取代阅读本身。当"继续写脚本 / 处理哈希 / 重建中间产物"与"继续通读原文 / 理清角色与称谓关系"竞争，且前者不是解决当前具体阻塞所必需时，优先后者。

对以下内容优先寻找上下文再翻译：`INFO`（NPC 台词）、`DIAL`（对话主题 / 玩家选项 / Topic）、`QUST`（任务名 / 目标 / 日志 / 阶段）、`BOOK`（书籍 / 信件 / 笔记）、角色 / 地点 / 派系 / 法术 / 装备 / 剧情专名。对话类文本尽可能结合所属任务、Topic / 分支、前后相邻台词、说话者身份、玩家选项与 NPC 回答的关系、当前剧情阶段。XML 无法提供足够上下文时，明确这是上下文缺失，不凭空补剧情。

## 2. 信息揭示顺序、角色知识边界与禁止剧透

保留原文的信息揭示顺序。因翻译提前暴露身份、真相、阵营关系、种族关系、人物关系、地点性质或其他剧情信息，是严重翻译事故。Agent 只能翻译"原文在当前文本位置允许玩家知道的信息"，不能把通读全文、世界观资料或后续剧情得来的真相提前写进译文。

警惕：专名与描述性通称；真名、化名、别名、绰号与伪装身份；古称、现代称呼与后世称呼；未知种族 / 势力与其后被揭示的真实身份；同一实体在不同角色、文化、时代或知识层级下的不同称谓；后续剧情才确认的亲缘、阵营、背叛、变身、来源或真实用途。

两个英文词即使在世界观层面最终指向同一实体，也不因此自动合并译名。原文选择了不同词形、称谓或描述时，默认差异可能具有叙事意义，确认无害前保留差异。例如：即使知道 `Falmer` 与 `Snow Elf` 存在身份关系，也不能在原文使用 `Falmer` 的位置提前译成"雪精灵"——这会破坏《黎明守卫》的身份揭示；`Maormer` / `Sea Elf` 同理。

完整通读带来的世界观真相用于避免误译、理解伏笔、保持前后一致，不用于把后见之明反向注入早期译文。

## 3. 原版词典的使用规则

`dictionary/` 下的官方英中 XML 是高优先级参考语料。目录采用目录语义：树下所有 XML 都是官方来源，不假设固定文件名、数量、子目录或 DLC 白名单，不基于已知文件名设优先级；新增 XML 自动参与查询。

优先用于：官方角色名、地名、派系名、法术 / 魔法效果 / 技能 / 装备术语、常见 UI 与交互文本、TES 世界观固定译法。

词典提供的是译名与用法证据，不是无条件语义替换表。命中只说明某译法在某些官方文本中成立，不自动证明两个不同英文术语在当前剧情中可以合并。专名、通称、别称、古称或描述性名称在原文中被明确区分时，即使词典表明它们最终指向同一对象，也先保留词汇层级差异，检查是否涉及剧情揭示、角色知识边界或文化视角。MOD 自创术语与原版术语冲突时，区分"原版固定译名"与"MOD 自创概念"。

## 4. 翻译风格

目标：像《天际》现有中文本地化的一部分，而非现代网络文本或机器直译。

默认要求：准确优先于华丽；中文自然，不保留无意义英文语序；人物口吻与身份和场景匹配；古朴感适度，不滥用文言；UI、任务目标与交互提示简洁；书籍、信件与剧情文本可适当提高文学性；同一角色、地点、派系、物品、概念的译名保持一致。不为了"像奇幻作品"添加原文不存在的信息、语气或修辞。

## 5. 按记录类型处理

不同 `REC` 类型共用一套机械策略。初步原则：

- `INFO:*`：优先保证人物口吻、上下文与指代正确。
- `DIAL:*`：简洁，注意它可能是玩家选项、Topic 名或对话标签。
- `QUST:*`：任务名可有风格；目标与日志优先清楚、自然、符合游戏 UI。
- `BOOK:*`：结合全文上下文翻译，不逐句割裂。
- `MESG:*`：按实际用途区分标题、正文、按钮与系统提示。
- `MGEF:*` / `SPEL:*`：优先复用原版魔法术语与描述习惯。
- `WEAP:*` / `ARMO:*` / `MISC:*`：优先保证名称风格与术语一致性。
- `ACTI:*` / `FURN:*`：交互文本通常短而明确。
- `NPC_:*` / `CELL:*` / `WRLD:*`：名称必须检查是否已有官方或既定译法。

这些规则随实际 MOD 样本细化；细化结果更新本 skill 或项目级 `GLOBAL.md`。
