## 事实、推断与未知

**已观察事实**：根目录存在该字面文件，内容为 CMD 风格的命令无法识别诊断；被识别失败的命令名是 PowerShell cmdlet `Select-String`。

**强推断**：执行链中有 CMD 解析了 PowerShell 命令；字面 `$null` 被当作文件目标，而非 PowerShell 的空值。是否是工具默认路由到 CMD、显式调用 CMD 或嵌套 shell 导致，尚不能确认。

**未核实**：原始完整工具调用、重定向符号、流合并方式、具体 Agent 与发生时间。诊断通常来自 stderr，因此不能仅凭样本把原命令定为 `> $null`；`2>`、`2>&1` 或外层流捕获均需原始调用证据验证。

本样本没有证明正式译文遭到截断，也没有证明失败后执行了后续命令。不要将潜在风险写成已发生事故。

## 机制与安全边界

Shell 通常在执行命令主体前处理输出重定向，因此目标文件可能先被创建或截断，随后命令才因不存在而失败。命令失败不等于没有文件副作用。

- 以当前工具契约和显式 shell 参数为准，不按操作系统或旧平台经验猜 shell。普通命令不引入多层 shell 嵌套。
- 首次运行与排错保留 stderr，不把错误重定向到所谓空设备。PowerShell、CMD 与 POSIX 的变量、转义和空设备语法不混用。
- 转义、语法或重定向失败后，停止当前命令链，核对工作目录新增项及预定输出目标；确认副作用后再修复重试。
- 不用 shell 重定向覆盖正式 XML、翻译结果或源码；源码走结构化编辑，XML 走确定性 writer。生成型工具先输出到新路径并验证，覆盖正式数据遵守对应工具授权与安全契约。
